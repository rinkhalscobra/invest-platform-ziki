Introduction
Production URL: https://live.galiapay.com

Sandbox URL: https://api.sandbox.galiapay.com

Welcome to the Payment API documentation. This API provides a comprehensive payment processing solution that enables you to accept payments, manage transactions, and handle payment-related operations with ease.
Overview

This API allows you to:

    Process Payments: Accept and process payments securely through multiple payment gateways
    Manage Transactions: Track, retrieve, and manage payment transactions
    Handle Webhooks: Receive real-time notifications about payment events

Getting Started

To get started with the Payment API:

    Authentication: Obtain your API key from our integration team.
    Make Your First Request: Try out the endpoints using the interactive examples below.
    Handle Responses: Process API responses and handle errors appropriately.
    Webhooks Setup: Configure webhook endpoints to receive payment notifications.
    Signature Verification: Implement webhook signature verification for security (see below).

API Conventions

This API follows REST principles and returns JSON responses. All requests should include:

    Content-Type: application/json header
    Accept: application/json header
    Authentication credentials (see Authentication section below)

Response Format

Error responses include detailed information to help you troubleshoot:

{
    "status": "ERROR",
    "message": "Error description",
    "errors": {}
}

API requests are subject to rate limiting to ensure service quality. Rate limit information is included in response headers.
Webhook Security (IPN Signatures)

All Instant Payment Notification (IPN) webhooks include HMAC-SHA256 signatures to ensure authenticity and integrity. It is strongly recommended that you verify these signatures before processing webhook notifications.
Webhook Headers

Each IPN request includes three security headers:

    X-Signature: HMAC-SHA256 signature of specific payload fields (64 hexadecimal characters)
    X-Timestamp: Unix timestamp when the IPN was sent
    X-Request-ID: Unique identifier (UUID v7) for tracking and idempotency

Webhook Payload

The webhook payload includes transaction data, customer information, and security fields:

{
  "uuid": "transaction-uuid",
  "referenceNo": "REF123",
  "returnUrl": "https://example.com/return",
  "status": "APPROVED",
  "amount": 10000,
  "currency": "USD",
  "timestamp": 1234567890,
  "requestId": "018e1234-5678-7abc-def0-123456789abc",
  "transaction": { ... },
  "customerInfo": { ... }
}

Important: The signature is computed using only specific fields (amount, currency, referenceNo, requestId, returnUrl, status, timestamp, uuid) in alphabetical order, not the entire payload.
Signature Verification

To verify the webhook signature:

    Extract the X-Signature header value
    Create a payload object with ONLY these fields in alphabetical order: amount, currency, referenceNo, requestId, returnUrl, status, timestamp, uuid
    Generate HMAC-SHA256 hash of the JSON-encoded signature payload using your API key as the secret
    Compare the generated signature with the header value using timing-safe comparison

PHP Example:

function verifyIpnSignature(array $payload, string $signature, string $apiKey): bool
{
    // Extract only the fields used for signature (in alphabetical order)
    $signaturePayload = [
        'amount' => $payload['amount'],
        'currency' => $payload['currency'],
        'referenceNo' => $payload['referenceNo'],
        'requestId' => $payload['requestId'],
        'returnUrl' => $payload['returnUrl'],
        'status' => $payload['status'],
        'timestamp' => $payload['timestamp'],
        'uuid' => $payload['uuid'],
    ];

    $jsonPayload = json_encode($signaturePayload, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE);
    $expectedSignature = hash_hmac('sha256', $jsonPayload, $apiKey);
    return hash_equals($expectedSignature, $signature);
}

Complete implementation examples in PHP, JavaScript, and Python are available in the repository at docs/IPN_SIGNATURE_VERIFICATION.md.
Security Best Practices

    ✅ Always verify signatures before processing webhooks
    ✅ Validate the timestamp to prevent replay attacks (reject IPNs older than 5 minutes)
    ✅ Use timing-safe comparison functions (hash_equals, timingSafeEqual, compare_digest)
    ✅ Store your API key securely (never commit to version control)
    ✅ Log failed verification attempts for security monitoring
    ✅ Return 2xx status codes for valid webhooks to prevent retries
